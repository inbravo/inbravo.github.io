KPI Differentiated Play

Not the harness — what makes the harness useful

Platform companies build L3 infrastructure. KPI builds the opinionated utilities and configurations that sit on top — specific to enterprise domains, measurable before/after. The same model Tredence used for semantic-layer token efficiency: don't build the database, build the utility that tests the database's quality for AI use.

Semantic Layer AI Readiness Score
Build
Audits LookML, dbt metrics, or Tableau extensions for AI-readiness. Runs test agent queries before and after, measures token reduction % and answer accuracy delta. Produces a ranked fix list.
Anchors in BI practice — KPI already implements semantic layers for clients.
Golden Dataset Factory
Build
Generates domain eval suites from existing BI reports. Extracts known Q&A pairs → structures as RAGAS-compatible eval cases → wires to CI. Compresses 6-week eval construction to days.
High reuse across verticals — every client has BI reports; almost none have structured eval suites.
Context Compression Benchmarker
Build
Tests chunking strategies, embedding models, and retrieval parameters against a client's document corpus. Measures token efficiency vs. answer faithfulness. Outputs an optimal "context recipe."
40–70% token reduction routinely available. Most clients never measure it.
Agent Output Consistency Checker
Build
Tests whether an agent returns semantically equivalent answers to rephrased questions. Flags divergence beyond a threshold. Produces a "consistency score" — a key audit metric for financial agents under EU AI Act Art. 9.
BFSI regulators require version-controlled test metrics. This is the simplest metric that maps to that requirement.
Data-to-Agent Contract Validator
Build
YAML metadata spec overlaid on Unity Catalog or Snowflake Horizon — annotates data assets with AI-consumption rules: PII sensitivity, allowed agents, business rules. Validates agent data access before promotion.
Extends existing data platform engagement into AI governance with no custom harness required.

Structural Gap

Training-time safety ≠ runtime governance

Constitutional AI and Model Spec are behavioral priors baked into model weights. They reduce the probability of harmful outputs. They provide no RBAC, no audit trail, no circuit breakers. This is a structural gap — not a product lag.

Training-time safety
Constitutional AI · Model Spec · RLHF
Governs model behavior at inference. The model "tries" to refuse harmful requests. Can be overridden by a sufficiently adversarial system prompt.
✓ Reduces probability of harmful outputs
✓ Refusal classifiers in model weights
✗ No RBAC — anyone with an API key gets the same model
✗ No audit trail — model doesn't log tool calls
✗ No circuit breakers — model doesn't halt after N iterations
✗ No delegation-chain enforcement
Runtime governance
What enterprises must build or configure
Enforcement happens outside model weights — at the gateway, in the harness, in the orchestration layer. This is what regulated enterprises require.
✗ RBAC (who can call what agent / tool)
✗ Audit trail of every tool call and hop
✗ Rate / cost circuit breakers per agent
✗ PII redaction layer (GDPR, HIPAA)
✗ Prompt injection defense (OWASP ASI01)
✗ Human approval gates (EU AI Act Art. 14)

Business model tension: model providers monetize on token consumption; governance controls that limit consumption are economically adverse.
