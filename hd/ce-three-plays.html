Play 2A · Parallel
Ontology Accelerators

Domain context packages that make AI agents answer correctly — built in the platform's own format, reusable across engagements.

What gets built
  • Databricks metric view YAML packages (Genie ontology layers)
  • Snowflake semantic view YAML with verified example queries
  • Apache Iceberg as the cross-platform bridge — write-once, reason-anywhere
  • Domain-specific vocabulary: SKOS, OWL 2, SHACL constraints
Starting domains
  • Insurance — loss ratio variants, IFRS 17 metrics, underwriting rules
  • BFSI — risk metrics, regulatory reporting dimensions
  • Reusable per domain, not rebuilt per customer
10.6% → 52.1%
Same model, same data. Accuracy improvement is from context engineering alone — no retraining, no model swap. This is the SI's leverage point.
The 5-layer context stack
  • L1 Taxonomy — labels, synonyms, preferred terms (SKOS)
  • L2 Semantic Layer — business questions mapped to queries
  • L3 Ontology — class hierarchy, inference rules, constraints (OWL 2)
  • L4 Knowledge Graph — persisted facts and relationships (RDF)
  • L5 Context Graph — live runtime state (event streams)
Ontology reference — stack, platforms, insurance examples
Play 2B · Parallel
AgentOS · Harness

Multi-agent control plane that decides which agent acts, at what quality, latency, and cost — governance is built in, not bolted on.

What gets built
  • Agent harness: per-agent governance wrapper — RBAC, audit trail, circuit breakers
  • Orchestration layer: LangGraph / AG2 for multi-agent delegation chains
  • Tool registry and agent identity — who called what and why
  • Eval pipeline: hallucination detection, output validation, regression
Decision economics
  • Not just "does the agent run" — which path meets quality and policy thresholds at lowest cost
  • Budget enforcement at orchestrator level (cost per business outcome)
  • Model routing: pick the most economical model that clears the quality floor
  • Latency and risk trade-offs surfaced as runtime decisions, not config
4-layer AgentOS taxonomy
L1 Framework · L2 Orchestration · L3 Agent Harness (per-agent governance) · L4 Agent Management Platform. The SI builds L2 and L3; L4 is Microsoft / IBM / ServiceNow territory.
Governance requirements addressed
  • OWASP Agentic AI Top 10 — prompt injection, tool poisoning, uncontrolled iteration
  • EU AI Act Art. 9 risk management (Class 5 autonomous agents)
  • NIST AI RMF — Govern / Measure / Manage functions
  • AIUC-1 AI Usage Controls certification alignment

How 2A and 2B reinforce each other

The ontology accelerators produce the context packages that agents reason over. The AgentOS harness governs which agent accesses that context, at what cost, within what policy. Play 2A raises answer quality; Play 2B controls the runtime conditions under which that quality is reliably delivered. Neither is complete without the other — which is why both should start from the same gap register, in parallel.
