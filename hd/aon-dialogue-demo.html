The Problem

Three definition gaps that block every marketing KPI

AON's MDL working document records these gaps explicitly — they are confirmed issues in the data, not hypothetical risks. Context Engineering closes them by encoding agreed definitions once, in Unity Catalog, where every downstream tool reads the same answer.

The Attribution War

marketing_sourced_pipeline has no agreed rule. Marketing filters C_Lead_Source___Original1 from Eloqua. Sales pulls lead_source from Aon Connect. Different fields. Different filters. Different numbers — every board meeting.

The MQL Mirage

There is no is_mql flag in the MDL schema. MQL must be derived from lead_status_code and lead_stage. Every analyst re-derives it differently. Campaign conversion rates are incomparable across teams.

The Invisible Event

Cvent event data flows into MDL via an Eloqua CDO. The five-hop join to pipeline opportunities exists but is undocumented. No attribution window is defined. The event team cannot answer: "Did our London Forum generate pipeline?"

The Solution

Context Engineering is a methodology, not a layer

CE is the practice of encoding business intent — what a metric means, what qualifies, what's excluded — directly into the data platform, as three permanent artifacts. Every downstream consumer reads the same definition. The attribution war ends because there is only one place the rule lives.

ARTIFACT 01

UC Column COMMENT

An ALTER COLUMN … COMMENT on lead_attributes_it.lead_source encodes the agreed allowlist and prohibits ad-hoc filters. Genie reads this before generating any SQL.

ARTIFACT 02

Unity Catalog Metric View

A YAML definition in Unity Catalog with a measures block. The expr contains the exact SQL. synonyms ensure "marketing pipeline" and "sourced pipeline" resolve to the same governed measure.

ARTIFACT 03

Genie Knowledge Store

A serialized_space that tells Genie: MQL is defined by status code, not a flag. Marketing-sourced requires the allowlist. Event attribution uses the 90-day window. Trusted SQL assets are pre-verified.

One source, two outputs: The same Metric View definition that governs Genie conversations also feeds Power BI Copilot via the Databricks Semantic Bridge. The attribution rule is written once and versioned in Unity Catalog. There is no separate BI semantic model to maintain.

Marketing Pipeline Metric View

Governed marketing_sourced_pipeline and mql_volume measures

# marketing.mdl.mv_marketing_pipeline
version: 1.1
source: marketing.mdl.lead_attributes_it
comment: "MDL Marketing Pipeline — governed layer"
filter: lead_status_code != 'DELETED'

joins:
  - name: opty
    source: marketing.mdl.opportunity_attributes_iit
    on: source.lead_id = opty.opty_lead_id

measures:
  - name: Marketing Sourced Pipeline
    expr: SUM(CASE WHEN lead_source IN (
        'Event','Content Syndication',
        'Paid Social','Webinar',
        'Email Campaign')
      THEN opty.opty_amount_usd END)
    synonyms: ["marketing pipeline",
               "sourced pipeline"]

  - name: MQL Volume
    expr: COUNT(CASE WHEN
        lead_status_code = 'QUALIFIED'
        AND lead_stage = 'MQL'
      THEN lead_id END)
        # note: lead_comverted_date (one 'n')
    synonyms: ["qualified leads","MQLs"]

Event Attribution Metric View

Governs the Cvent → pipeline 90-day attribution window

# marketing.mdl.mv_event_attribution
version: 1.1
source: marketing.mdl.opportunity_attributes_iit

joins:
  - name: contact
    source: marketing.mdl.contact_it
    on: source.opty_primary_contact_id
       = contact.con_party_id
  - name: event
    source: marketing.mdl.cmpgn_campaigns_it
    on: contact.campaign_cvent_id
       = event.campaign_cvent_id

measures:
  - name: Post-Event Pipeline 90d
    expr: SUM(CASE WHEN
        DATEDIFF(opty_record_creation_date,
                 event.event_start_date)
        BETWEEN 0 AND 90
      THEN opty_amount_usd END)
    comment: "90d window — CMO sign-off to change"
    synonyms: ["event pipeline",
               "conference pipeline",
               "post-event attribution"]

/* Genie Space: AON Marketing Intelligence
   Space: aon-marketing-mdl-prod              */

-- MQL DEFINITION
INSTRUCTION:
  "MQL = lead_status_code='QUALIFIED'
   AND lead_stage='MQL'.
   NO standalone mql_flag in MDL.
   Conversion field: lead_comverted_date
   (note: one 'n' — actual schema spelling)."

-- ATTRIBUTION RULE
INSTRUCTION:
  "Always use Metric View for marketing
   pipeline — never raw lead_source filter.
   Eloqua and Aon Connect stamp different
   lead_source values."

-- TRUSTED ASSET: Pipeline QTD
TRUSTED_ASSET marketing_pipeline_qtd:
  SELECT lead_source,
    COUNT(lead_id)       AS lead_count,
    SUM(opty_amount_usd) AS pipeline_usd
  FROM MEASURE(marketing_sourced_pipeline)
  WHERE opty_record_creation_date
    >= DATE_TRUNC('quarter',CURRENT_DATE())
  GROUP BY 1 ORDER BY 3 DESC;

CREATE TABLE IF NOT EXISTS marketing.lead_attributes_it (
  lead_id            STRING    NOT NULL,
  lead_status_code   STRING,   -- 'QUALIFIED' signals MQL stage
  lead_stage         STRING,   -- 'MQL' | 'SAL' | 'SQL' | 'Recycled'
  lead_source        STRING,   -- from Aon Connect (sales view)
  lead_comverted_date DATE,    -- NOTE: one 'n' — actual MDL spelling
  created_date       DATE,
  owner_id           STRING,
  campaign_id        STRING,
  campaign_cvent_id  STRING   -- FK to SYS_Cvent_Event.Event_Code
)
COMMENT 'Lead records sourced from Aon Connect (Oracle Sales Cloud). lead_source reflects the Sales CRM field; use C_Lead_Source___Original1 from eloqua_contacts for first-touch attribution.';

ALTER TABLE marketing.lead_attributes_it
  ALTER COLUMN lead_source
  COMMENT 'Agreed allowlist for marketing-sourced attribution (Oct 2026, CMO sign-off): Event, Content Syndication, Paid Social, Webinar, Email Campaign. Any value outside this list is attributed to Sales.';

ALTER TABLE marketing.lead_attributes_it
  ALTER COLUMN lead_status_code
  COMMENT 'MQL derivation rule (agreed Oct 2026): a lead is MQL when lead_status_code = QUALIFIED AND lead_stage = MQL. No pre-built is_mql flag exists in MDL — always derive using both fields.';

-- ── opportunity_attributes_iit ──────────────────────────────
CREATE TABLE IF NOT EXISTS marketing.opportunity_attributes_iit (
  opty_id            STRING    NOT NULL,
  opty_lead_id       STRING,   -- FK to lead_attributes_it.lead_id
  opty_amount_usd    DECIMAL(18,2),
  opty_stage         STRING,
  opty_close_date    DATE,
  opty_created_date  DATE,
  fiscal_quarter     STRING
)
COMMENT 'Opportunity records from Aon Connect. Join to leads via: lead_id = opty_lead_id. Note table suffix is double-i (iit), not single.';

-- ── cmpgn_campaigns_it ──────────────────────────────────────
CREATE TABLE IF NOT EXISTS marketing.cmpgn_campaigns_it (
  campaign_id        STRING    NOT NULL,
  campaign_name      STRING,
  campaign_type      STRING,   -- 'Event' | 'Email' | 'Webinar' | 'Paid Social'
  campaign_region    STRING,
  event_start_date   DATE,
  cvent_event_code   STRING   -- links to lead_attributes_it.campaign_cvent_id
)
COMMENT 'Campaign master sourced from Eloqua. Event attribution window: 90 days from event_start_date (agreed Oct 2026). Use cvent_event_code to join to lead records via campaign_cvent_id.';

-- ── eloqua_contacts (ELQ_Contacts) ──────────────────────────
CREATE TABLE IF NOT EXISTS marketing.eloqua_contacts (
  contact_id                  STRING  NOT NULL,
  lead_id                     STRING,
  C_Lead_Source___Original1   STRING,  -- first-touch source from Eloqua
  email_address               STRING,
  company                     STRING,
  country                     STRING,
  region                      STRING
)
COMMENT 'Eloqua contact master. C_Lead_Source___Original1 is the first-touch lead source as captured by Eloqua marketing automation — this is the authoritative field for marketing attribution, NOT lead_source from Aon Connect.';

ALTER TABLE marketing.eloqua_contacts
  ALTER COLUMN C_Lead_Source___Original1
  COMMENT 'First-touch lead source from Eloqua (Aon Connect stores a different lead_source field that reflects sales updates). Use this field — not lead_attributes_it.lead_source — when computing marketing_sourced_pipeline.';

-- ── campaign_member_it ───────────────────────────────────────
CREATE TABLE IF NOT EXISTS marketing.campaign_member_it (
  member_id       STRING  NOT NULL,
  campaign_id     STRING,
  lead_id         STRING,
  status          STRING,
  responded_date  DATE
)
COMMENT 'Campaign membership bridge between campaigns and leads. Use to count leads per campaign and to trace event attendance before pipeline join.';

-- ── SYS_Cvent_Event (Eloqua CDO) ─────────────────────────────
CREATE TABLE IF NOT EXISTS marketing.sys_cvent_event (
  Event_Code       STRING  NOT NULL,
  Event_Name       STRING,
  Event_Start_Date DATE,
  Registrant_Email STRING,
  Attendance_Status STRING
)
COMMENT 'Cvent event data ingested via Eloqua Custom Data Object. Join to campaigns via: cmpgn_campaigns_it.cvent_event_code = sys_cvent_event.Event_Code, then to leads via campaign_member_it.';

Two Metric View YAML files for Unity Catalog. Requires Databricks Runtime 17.2+ and Unity Catalog enabled. Deploy with the UC API or Databricks CLI (databricks unity-catalog metric-views create --file <yml>).
mv_marketing_pipeline.yml
name: mv_marketing_pipeline
catalog: aon_mdl_test
schema: marketing
comment: >
  Marketing-sourced pipeline and MQL metrics for AON MDL.
  Encoding the agreed attribution allowlist (Oct 2026) and MQL
  derivation rule so every BI tool reads the same governed numbers.

source:
  table: marketing.lead_attributes_it
  alias: l

joins:
  - table: marketing.opportunity_attributes_iit
    alias: o
    on: "l.lead_id = o.opty_lead_id"
    type: LEFT
  - table: marketing.eloqua_contacts
    alias: ec
    on: "l.lead_id = ec.lead_id"
    type: LEFT

fields:
  - name: fiscal_quarter
    expr: "o.fiscal_quarter"
    synonyms: ["quarter", "Q", "FQ"]
  - name: lead_source_group
    expr: >
      CASE
        WHEN ec.C_Lead_Source___Original1 IN
          ('Event','Content Syndication','Paid Social','Webinar','Email Campaign')
        THEN 'Marketing'
        ELSE 'Sales / Other'
      END
    synonyms: ["source", "channel", "attribution"]
  - name: campaign_region
    expr: "l.campaign_id"
    synonyms: ["region", "geography", "geo"]

measures:
  - name: marketing_sourced_pipeline
    expr: >
      SUM(CASE
        WHEN ec.C_Lead_Source___Original1 IN
          ('Event','Content Syndication','Paid Social','Webinar','Email Campaign')
        THEN o.opty_amount_usd ELSE 0 END)
    data_type: DECIMAL
    synonyms: ["marketing pipeline", "mktg pipeline", "marketing sourced revenue"]
    comment: >
      Pipeline amount attributable to marketing channels only.
      Uses Eloqua first-touch field C_Lead_Source___Original1, NOT
      lead_source from Aon Connect. Allowlist: Event, Content
      Syndication, Paid Social, Webinar, Email Campaign.

  - name: mql_volume
    expr: >
      COUNT(DISTINCT CASE
        WHEN l.lead_status_code = 'QUALIFIED'
         AND l.lead_stage = 'MQL'
        THEN l.lead_id END)
    data_type: INTEGER
    synonyms: ["MQLs", "qualified leads", "marketing qualified leads"]
    comment: >
      MQL derivation: lead_status_code = QUALIFIED AND lead_stage = MQL.
      No pre-built is_mql flag exists in MDL — always use both fields.

  - name: sql_converted_volume
    expr: >
      COUNT(DISTINCT CASE
        WHEN l.lead_stage = 'SQL'
        THEN l.lead_id END)
    data_type: INTEGER
    synonyms: ["SQLs", "sales qualified leads", "converted MQLs"]

  - name: mql_to_sql_conversion_rate
    expr: >
      ROUND(100.0 * COUNT(DISTINCT CASE WHEN l.lead_stage = 'SQL' THEN l.lead_id END)
        / NULLIF(COUNT(DISTINCT CASE
            WHEN l.lead_status_code = 'QUALIFIED' AND l.lead_stage = 'MQL'
            THEN l.lead_id END), 0), 1)
    data_type: DECIMAL
    synonyms: ["conversion rate", "MQL conversion", "lead conversion"]

  - name: lead_count
    expr: "COUNT(DISTINCT l.lead_id)"
    data_type: INTEGER
    synonyms: ["leads", "lead volume"]
mv_event_attribution.yml
name: mv_event_attribution
catalog: aon_mdl_test
schema: marketing
comment: >
  Event-to-pipeline attribution for AON MDL Cvent events.
  Encodes the agreed 90-day attribution window (Oct 2026, CMO sign-off
  required to change). Resolves the five-hop Cvent join chain into
  a single governed measure.

source:
  table: marketing.sys_cvent_event
  alias: ev

joins:
  - table: marketing.cmpgn_campaigns_it
    alias: c
    on: "ev.Event_Code = c.cvent_event_code"
    type: LEFT
  - table: marketing.campaign_member_it
    alias: cm
    on: "c.campaign_id = cm.campaign_id"
    type: LEFT
  - table: marketing.lead_attributes_it
    alias: l
    on: "cm.lead_id = l.lead_id"
    type: LEFT
  - table: marketing.opportunity_attributes_iit
    alias: o
    on: "l.lead_id = o.opty_lead_id"
    type: LEFT

fields:
  - name: event_name
    expr: "ev.Event_Name"
    synonyms: ["event", "conference", "forum"]
  - name: event_date
    expr: "ev.Event_Start_Date"
    synonyms: ["event date", "date of event", "forum date"]

measures:
  - name: post_event_pipeline_90d
    expr: >
      SUM(CASE
        WHEN o.opty_created_date
          BETWEEN ev.Event_Start_Date
              AND DATE_ADD(ev.Event_Start_Date, 90)
        THEN o.opty_amount_usd ELSE 0 END)
    data_type: DECIMAL
    synonyms: ["post-event pipeline", "event pipeline", "pipeline from event"]
    comment: >
      Pipeline created within 90 days of the event start date.
      Attribution window: 90 days (agreed Oct 2026).
      CMO sign-off required to change the window.

  - name: post_event_pipeline_30d
    expr: >
      SUM(CASE
        WHEN o.opty_created_date
          BETWEEN ev.Event_Start_Date
              AND DATE_ADD(ev.Event_Start_Date, 30)
        THEN o.opty_amount_usd ELSE 0 END)
    data_type: DECIMAL
    synonyms: ["30-day event pipeline"]

  - name: post_event_opportunity_count
    expr: >
      COUNT(DISTINCT CASE
        WHEN o.opty_created_date
          BETWEEN ev.Event_Start_Date
              AND DATE_ADD(ev.Event_Start_Date, 90)
        THEN o.opty_id END)
    data_type: INTEGER
    synonyms: ["event opportunities", "opps from event", "deals from event"]

setup_genie_space.py
from databricks.sdk import WorkspaceClient
from databricks.sdk.service.dashboards import (
    GenieSpace, GenieSpaceDataset, GenieSpaceInstruction,
    GenieSpaceTrustedQuery
)

w = WorkspaceClient()  # reads DATABRICKS_HOST + DATABRICKS_TOKEN from env

# ── 1. Create the Genie Space ────────────────────────────────────
space = w.genie.create(
    GenieSpace(
        title="AON Marketing Data Lake — CE Demo",
        description="Context-engineered analytics space for the AON MDL."
                     " Uses governed Metric Views for consistent KPIs.",
        warehouse_id="<your-sql-warehouse-id>",  # replace
    )
)
space_id = space.space_id
print(f"Created space: {space_id}")

# ── 2. Add Metric View datasets ──────────────────────────────────
for mv_name in ["mv_marketing_pipeline", "mv_event_attribution"]:
    w.genie.create_space_dataset(
        space_id=space_id,
        dataset=GenieSpaceDataset(
            display_name=mv_name,
            table=f"aon_mdl_test.marketing.{mv_name}",
        )
    )

# ── 3. Load standing instructions (knowledge store) ──────────────
INSTRUCTIONS = [
    "ALWAYS use mv_marketing_pipeline for any question about pipeline, revenue, or MQLs.",
    "ALWAYS use mv_event_attribution for any question about events, conferences, or forums.",
    "For marketing-sourced pipeline: use the marketing_sourced_pipeline measure."
     " Do NOT filter on lead_attributes_it.lead_source — that is the Sales CRM field."
     " The attribution logic is already encoded in the Metric View.",
    "For MQL counts: use the mql_volume measure from mv_marketing_pipeline."
     " Do NOT attempt to derive MQLs manually — the two-field rule is in the Metric View.",
    "For post-event pipeline: always use post_event_pipeline_90d from mv_event_attribution."
     " The 90-day window is the agreed standard. CMO sign-off is required to change it.",
]

for text in INSTRUCTIONS:
    w.genie.create_space_instruction(
        space_id=space_id,
        instruction=GenieSpaceInstruction(instruction=text)
    )

# ── 4. Add trusted (sample) queries ──────────────────────────────
TRUSTED_QUERIES = [
    {
        "display_name": "Q3 Marketing-Sourced Pipeline",
        "query": """
SELECT lead_source_group,
       COUNT(DISTINCT lead_id)      AS lead_count,
       SUM(marketing_sourced_pipeline) AS pipeline_usd,

v1_attribution_gap.sql — run BEFORE CE to see the conflict
-- Shows the raw conflict: Sales field vs Eloqua first-touch field
-- Marketing sees $58.4M (Eloqua C_Lead_Source___Original1)
-- Sales sees   $21.2M (Aon Connect lead_source)
-- Gap: $37.2M — same leads, different attribution field

SELECT
  'Eloqua first-touch (Marketing view)'  AS attribution_method,
  ec.C_Lead_Source___Original1           AS lead_source,
  COUNT(DISTINCT l.lead_id)             AS leads,
  SUM(o.opty_amount_usd)               AS pipeline_usd
FROM   marketing.lead_attributes_it l
JOIN   marketing.opportunity_attributes_iit o  ON l.lead_id = o.opty_lead_id
JOIN   marketing.eloqua_contacts ec           ON l.lead_id = ec.lead_id
WHERE  o.fiscal_quarter = 'Q3-2026'
GROUP BY ec.C_Lead_Source___Original1

UNION ALL

SELECT
  'Aon Connect field (Sales view)'       AS attribution_method,
  l.lead_source,
  COUNT(DISTINCT l.lead_id),
  SUM(o.opty_amount_usd)
FROM   marketing.lead_attributes_it l
JOIN   marketing.opportunity_attributes_iit o  ON l.lead_id = o.opty_lead_id
WHERE  o.fiscal_quarter = 'Q3-2026'
GROUP BY l.lead_source
ORDER BY attribution_method, pipeline_usd DESC;
