The Four-Era Evolution

Era 1
Prompt Engineering
2022–23
"What to say to the model"

Year one. Each user writes their own prompts. Works for demos and narrow tasks with stable scope.

What broke

Quality per user. Business rules in prompts go stale. Model updates silently degrade every prompt. 20–30% accuracy ceiling.

Cost failure

Every retry invisible. No budget cap. No session limit. Total cost of ownership hidden in human review time, not compute spend.

Era 2
Context Engineering
2024–25
"What the model needs to know" — methodology, not a layer

Centralises semantic context. Removes per-user variability. AI-available ≠ AI-consumable.

What broke

Model knows what to know, not what to do. No stop rules. No optimization goal. Klarna: perfect context, wrong goal — $60M to rehire.

Cost failure

40% NL accuracy without semantic layer → 60% more failure-triggered retries. Multi-model setups add routing complexity CE doesn't address.

Era 3
Intent Engineering
2026
"What the model must achieve — within what limits" — methodology, not a layer

Huryn 8-component model: Strategy · Objectives · Stop Rules · Autonomy Boundaries. Encodes organizational goals, not just data.

What broke

Intent buried in code — not auditable or versioned. Model-coupled: swap Opus for Haiku = full re-engineering. Assumptions hidden in natural language.

Cost failure

No Stop Rules = agent refines past "good enough". 60% of agentic spend is in refinement loops with no exit condition.

Era 4
Specification Engineering
Emerging
"What can be proved — at what cost — by whom — at what version"

Versioned, model-agnostic specs. Clauses carry unique IDs. Example prompts are unit tests. Spec IS the regulatory artifact.

Still maturing

No dominant toolchain. No spec completeness standard. Most tools in Beta or Preview. Practitioner adoption early.

Cost breakthrough

Model-agnostic spec = swap Opus → Haiku freely under budget pressure. Only layer that reduces cost without reducing governance.

The failure chain

PE → CE
Each user supplied their own context → quality was unpredictable, every call was unique, no caching possible, hidden cost in human review time.
CE → IE
Context was governed, behavior was not → agents wandered past "good enough" with no exit condition, consuming 60% of budget in refinement loops.
IE → SE
Intent was encoded in code — couldn't be audited, ported, or proved. Model-coupled intent = can't swap to a cheaper model = cost locked in.

§4

AgentOS vs AgentHarness

Category terms, not single products. The market is converging on this vocabulary.

AgentHarness
The layer that runs agents
  • Wraps, controls, tests, monitors, evaluates the agent loop
  • LangGraph · CrewAI · AutoGen/AG2 · Mastra · OpenHarness
  • Observability: AgentOps · Langfuse · Phoenix (Arize)
  • Solves: agent loop management, tool calling, multi-agent handoffs
Does not solve: cost governance, regulatory audit, model portability
AgentOS
The layer that governs agents — sits above the harness
  • Policy engine — determines what agents can do, at what cost, in what order
  • MS Agent Governance Toolkit "Agent OS" component (YAML/OPA Rego/Cedar)
  • Databricks Unity AI Gateway — spend caps + smart routing
  • AWS AgentCore Policy — Cedar, temporal session auth
  • AG2 self-brands as "open-source AgentOS"
  • Solves: cost guardrails, action authorization, compliance evidence
Relationship
AgentHarness runs agents. AgentOS governs them. A spend cap in Databricks Unity AI Gateway is AgentOS. The LangGraph loop that executes is AgentHarness. Both are required. Neither replaces the other.

The Argument

Accountable AI, by design.
Every platform ships cost controls. Databricks has spend caps. AWS has Cedar. Microsoft has trust scoring. None of them know your business logic.
A spend cap that fires at the wrong point doesn't reduce cost — it breaks output.
CE makes context precise → fewer retries → lower token waste.
IE makes behavior bounded → fewer refinement loops → lower call volume.
SE makes intent portable → cheaper models viable → lower unit cost.
AgentOS enforces it at runtime → no runaway sessions → lower infrastructure spend.
That's the methodology gap the platforms can't sell you. The platform ships the controls. We ship the judgment about when to use them.
"The platform ships AI. We ship accountability."
